# UI Implementation Workflow

## Objective

Build clean, responsive, accessible, and reusable user interfaces that follow the existing DeployX design system.

Always reuse existing UI components before creating new ones.

---

## Phase 1 — Understand

Understand

- UI requirement
- User flow
- Expected interactions
- Responsive behavior

---

## Phase 2 — Inspect

Inspect

- Existing layouts
- Existing UI components
- Shared components
- Icons
- Theme
- Typography
- Spacing
- Existing pages

Determine whether existing components can be reused.

Never duplicate UI components.

---

## Phase 3 — Plan

Prepare

- Components to reuse
- New components (if required)
- Layout changes
- Responsive behavior
- State handling
- Accessibility requirements

---

## Phase 4 — Implement

Follow the existing design system.

Use

- React Functional Components
- Tailwind CSS
- Existing UI components
- Existing icons

Implement

- Responsive layout
- Loading state
- Error state
- Empty state

Never

- Hardcode colors
- Hardcode spacing
- Duplicate layouts
- Duplicate components
- Use inline styles unless necessary

---

## Phase 5 — Review

Run

- frontend-checklist
- accessibility-checklist
- performance-checklist
- feature-checklist

Verify

- Consistent spacing
- Consistent typography
- Consistent component usage

---

## Phase 6 — Verify

Confirm

- Mobile responsive
- Tablet responsive
- Desktop responsive
- Accessible
- No layout shifts
- No console errors

---

## Phase 7 — Output

Provide

- UI summary
- Components created
- Components reused
- Responsive verification
- Accessibility verification
